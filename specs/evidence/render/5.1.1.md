## 1. Unified Scene-Graph & Display List Architecture

`render-core` bridges `word-engine`, `excel-engine`, and `ppt-engine` into a hardware-accelerated, tile-virtualized graphics pipeline. The core abstraction is the **Display List**, an immutable sequence of low-level GPU drawing commands compiled each frame from the underlying office document models.

```
+-----------------------------------------------------------------------------------+
|                            OFFICE ENGINE MODELS                                   |
|   Word Engine (Pages)   |   Excel Engine (CSPG Grid)   |   PPT Engine (Shapes)    |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                          DISPLAY LIST COMPILERS                                   |
|    WordDisplayCompiler   |   ExcelDisplayCompiler     |    PptDisplayCompiler     |
+-----------------------------------------------------------------------------------+
                                          |
                       [Viewport Spatial Culling Index]
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                            GPU DISPLAY LIST                                       |
|  - PushClip / PopClip                                                             |
|  - PushTransform / PopTransform                                                   |
|  - DrawQuad (Instanced quads: cells, backgrounds, borders, selection)             |
|  - DrawText (Shaped GlyphRuns: subpixel BiDi / CJK / RTL runs)                    |
|  - DrawPath (Batched Bezier vector paths: DrawingML custom shapes, curves)        |
+-----------------------------------------------------------------------------------+
          |                                                               |
          v                                                               v
+------------------------+                                      +-------------------+
|  GPU BACKEND (WebGPU)  |                                      | HEADLESS FALLBACK |
|  Instanced VBO / EBO   |                                      | SVG / PNG Raster  |
+------------------------+                                      +-------------------+
```

## 2. GPU Draw Primitives

### 2.1 `QuadInstance`
Instanced 2D rectangle primitive rendered with a single instanced draw call:
- `rect: Rect2D` (origin $x, y$, dimensions $w, h$ in DIPs)
- `color: ColorRgba` (normalized floats $[r, g, b, a] \in [0.0, 1.0]$)
- `border_color: Option<ColorRgba>`
- `border_width: f32`
- `corner_radius: f32` (SDF rounded corners)
- `texture_id: Option<u32>`

### 2.2 `GlyphRun`
Shaped typographical run representing continuous text:
- `glyphs: Vec<GlyphInstance>` (glyph ID, relative subpixel position $(x, y)$, dimensions, UV coordinates in glyph atlas)
- `font_size_px: f32`
- `font_family: String`
- `color: ColorRgba`
- `bounds: Rect2D`
- `bidi_level: u8` (0 = LTR, 1 = RTL)
- `script: TextScript` (Latin, CJK, Arabic, Hebrew, Devanagari)

### 2.3 `BezierPathBatch`
DrawingML vector path geometry:
- `commands: Vec<PathCommand>` (MoveTo, LineTo, QuadTo, CubicTo, Close)
- `fill_color: Option<ColorRgba>`
- `stroke_color: Option<ColorRgba>`
- `stroke_width: f32`
- `bounds: Rect2D`

## 3. Spatial Indexing & Viewport Culling

To guarantee $< 2.0\text{ ms}$ display list generation across huge documents (e.g., $1,000,000$ Excel cells or 1,000 Word pages):

1. **Spatial Grid Partitioning:**
   - World space is divided into uniform tiles of size $T_{\text{size}} = 256 \times 256$ DIPs.
   - An object with bounding box $(x, y, w, h)$ is indexed into all intersecting tiles:
     $$c_{\min} = \lfloor x / T_{\text{size}} \rfloor, \quad c_{\max} = \lfloor (x + w) / T_{\text{size}} \rfloor$$
     $$r_{\min} = \lfloor y / T_{\text{size}} \rfloor, \quad r_{\max} = \lfloor (y + h) / T_{\text{size}} \rfloor$$

2. **Viewport Culling Query:**
   - Given visible viewport $V = (v_x, v_y, v_w, v_h)$:
   - Compute intersecting tile range $[C_{\min}, C_{\max}] \times [R_{\min}, R_{\max}]$.
   - Fast AABB intersection test filters candidate primitives:
     $$\text{Intersects}(A, B) = A.x < B.x + B.w \land A.x + A.w > B.x \land A.y < B.y + B.h \land A.y + A.h > B.y$$
   - Non-intersecting primitives are pruned immediately with zero memory allocation.

## 4. Engine Compilers

### 4.1 Word Display Compiler (`WordDisplayCompiler`)
- Iterates over pages in `DocumentLayout`.
- Culls pages whose bounding box $(0, y_{\text{page}}, w_{\text{page}}, h_{\text{page}})$ falls outside the viewport.
- Generates:
  1. Page drop shadow and white background (`DrawQuad`)
  2. Margin boundary guides (optional)
  3. Text line glyph runs (`DrawText`)
  4. Table cell borders and cell backgrounds (`DrawQuad`)
  5. Floating / inline DrawingML shapes (`DrawPath`, `DrawQuad`)

### 4.2 Excel Display Compiler (`ExcelDisplayCompiler`)
- Performs binary search on cumulative row heights and column widths to identify the visible cell window $[r_{\min}, r_{\max}] \times [c_{\min}, c_{\max}]$ in $O(\log R + \log C)$ time.
- Emits:
  1. Grid lines as instanced thin quads (`DrawQuad`)
  2. Cell background fills from styles (`DrawQuad`)
  3. Formatted cell text values (`DrawText`)
  4. Cell borders (thin, medium, double, dashed) (`DrawQuad`)
  5. Active selection highlight overlay (`DrawQuad` with alpha blending)
  6. Frozen panes with pinned coordinates (`PushClip`, `PushTransform`)

### 4.3 PowerPoint Display Compiler (`PptDisplayCompiler`)
- Centers slide canvas with aspect ratio preservation (16:9 widescreen or 4:3 standard).
- Compiles:
  1. Slide canvas background (`DrawQuad`)
  2. Master slide and slide layout background shapes (`DrawQuad`, `DrawPath`)
  3. Slide shapes in z-order (`ShapeTree` hierarchy)
  4. Dynamic animated / morphed scene states (`MorphedSlideState`) with continuous transforms and opacity blending.

## 5. Software Rasterizer & Headless Vector Exporter Fallback

For continuous integration, unit testing, and vector print export without requiring an active physical GPU:
1. **SVG Exporter (`export_svg`):**
   Converts a `DisplayList` into standard, deterministic W3C SVG XML (`<svg>`, `<rect>`, `<text>`, `<path>`, `<clipPath>`).
2. **Software Pixel Rasterizer (`render_to_pixels`):**
   Draws quads, text, and lines into an RGBA pixel buffer ($32\text{-bit}$ premultiplied alpha) with anti-aliasing and subpixel blending.
3. **PDF Vector Stream Writer (`export_pdf_stream`):**
   Generates standard PDF page description vector streams (`q`, `cm`, `re`, `f`, `BT`, `Tf`, `Tj`, `ET`, `Q`).
