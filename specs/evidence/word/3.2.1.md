## 1. Clean-Room Reverse Engineering Analysis: Line-Breaking & Pagination

### 1.1 Text Measurement, Kerning & Whitespace Compression

WordprocessingML measures typographic boundaries in twips ($1\text{ pt} = 20\text{ twips}$; $1\text{ inch} = 1440\text{ twips}$).

#### 1.1.1 Character Advance & Ascent/Descent
For a character $c$ rendered with font size $S$ half-points ($S/20\text{ pt}$):
- Base em-box height: $E_{\text{twips}} = S \cdot 10\text{ twips}$.
- Advance width:
  $$W_{\text{advance}}(c) = \lfloor \frac{E_{\text{twips}} \cdot \text{fraction}_{\text{em}}(c)}{1000} \rfloor$$
- Ascent and Descent:
  $$H_{\text{ascent}} = \lfloor \frac{E_{\text{twips}} \cdot 800}{1000} \rfloor, \quad H_{\text{descent}} = \lfloor \frac{E_{\text{twips}} \cdot 200}{1000} \rfloor$$

#### 1.1.2 Kerning Pair Adjustments
When character kerning is enabled for font size $S \ge 2 \cdot \text{kern}_{\text{threshold}}$, adjacent glyph pairs $(c_1, c_2)$ receive horizontal kerning adjustments:
$$W_{\text{kern}}(c_1, c_2) = \frac{E_{\text{twips}} \cdot \text{kern\_table}(c_1, c_2)}{1000}$$
For example, ('A', 'V') applies $-80 / 1000$ em-units ($-38\text{ twips}$ at 24pt).

#### 1.1.3 Whitespace Compression at Line Ends
In Microsoft Word's line-breaking engine, trailing spaces at the end of a line do not contribute to line overflow. When computing line breaks, trailing whitespace is compressed or excluded from the overflow check, preventing solitary trailing spaces from creating accidental line wraps.

#### 1.1.4 Non-Breaking Spaces and Soft Hyphens
- **Non-Breaking Space (`\u{00A0}`):** Treated as an indivisible word token (`can_break_after: false`), preventing hyphenation or line breaks between bound terms (e.g., `"100 USD"`).
- **Soft Hyphen (`\u{00AD}`):** Formatted with $0$ width when unbroken inside a line. When a line breaks at a soft hyphen, it renders an explicit hyphen glyph (`-`) with full advance width and line break penalty.

## 2. Kinsoku Shori (CJK Line Breaking) Rules

ECMA-376 §17.3.1.15 specifies Kinsoku Shori rules for East Asian typography:

### 2.1 Prohibited Line-Start Characters (Gyoutou Kinsoku)
A line must **never** start with closing punctuation, sentence terminators, or closing brackets:
$$K_{\text{start}} = \{ ), ], \}, >, », ”, ’, 」, 』, ）, 〕, 】, 》, 〉, ｝, ］, ,, ., !, ?, ;, :, ，, 。, 、, ．, ！, ？, ；, ：, …, —, ー, \%, ‰, °, ℃, ℉ \}$$

### 2.2 Prohibited Line-End Characters (Gyoumatsu Kinsoku)
A line must **never** end with opening punctuation or currency prefixes:
$$K_{\text{end}} = \{ (, [, \{, <, «, “, ‘, 「, 『, （, 〔, 【, 《, 〈, ｛, ［, \$, ¥, £, €, №, \# \}$$

When a tentative line break would violate these rules, the breaking engine pulls the prohibited character to the previous line (compressing whitespace) or moves the preceding character to the next line.

## 3. Knuth-Plass Total-Fit vs Greedy Hybrid Line Breaker

The `LineBreaker` architecture provides two complementary breaking strategies:

```
                            Paragraph Stream
                                   |
                                   v
                      +--------------------------+
                      | Tokenizer & Measurements |
                      +------------+-------------+
                                   |
               +-------------------+-------------------+
               |                                       |
    (Left/Right/Center or Fast Typing)        (Justified w:jc="both")
               v                                       v
      +-----------------+                     +-----------------+
      |  Greedy Breaker |                     |   Knuth-Plass   |
      |  O(N) Fast Path |                     | Total-Fit DP    |
      +--------+--------+                     +--------+--------+
               |                                       |
               +-------------------+-------------------+
                                   |
                                   v
                        +----------------------+
                        | Formatted Line Boxes |
                        +----------------------+
```

### 3.1 Knuth-Plass Total-Fit Dynamic Programming
For justified paragraphs (`w:jc val="both"` or `val="distribute"`), lines are optimized globally across the entire paragraph:
- Let $W_{\text{target}}$ be the column width minus paragraph indents ($W_{\text{col}} - \text{indent}_{\text{left}} - \text{indent}_{\text{right}}$).
- For candidate line slice $i \to j$:
  $$\Delta_{i,j} = W_{\text{target}} - W_{i,j}$$
- Demerit score:
  $$D_{i,j} = \begin{cases} \infty & \text{if } \Delta_{i,j} < -100\text{ (overfull)} \\ 0 & \text{if } j = N \text{ and } \Delta_{i,j} \ge 0\text{ (last line loose)} \\ (\Delta_{i,j})^2 & \text{otherwise} \end{cases}$$
- The Bellman shortest-path recurrence computes optimal breaks in $O(N)$ active states:
  $$E(j) = \min_{i < j} \{ E(i) + D_{i,j} \}, \quad E(0) = 0$$

### 3.2 Greedy Breaker (Fast Path)
For left/right/center aligned text or interactive keystroke editing, the greedy breaker evaluates tokens sequentially in $O(N)$ time with $< 50\,\mu\text{s}$ execution, satisfying the GEC $< 1.0\text{ ms}$ keystroke SLA.

## 4. Paragraph Line Height & Alignment Geometry

### 4.1 Line Spacing Rules (`w:spacing`)
Let $S_{\text{max}}$ be the maximum font size among tokens on the line:
- **`auto` (`w:lineRule="auto"`):**
  $$H_{\text{line}} = \lfloor \frac{S_{\text{max}} \cdot 10 \cdot 115}{100} \rfloor \times \frac{\text{line}}{240}$$
  (e.g., $12\text{pt}$ with single spacing $\to 240 \times 1.15 = 276\text{ twips}$).
- **`exact` (`w:lineRule="exact"`):**
  $$H_{\text{line}} = \text{line}$$
- **`atLeast` (`w:lineRule="atLeast"`):**
  $$H_{\text{line}} = \max(H_{\text{natural}}, \text{line})$$

### 4.2 Horizontal Alignment Coordinate Offsets
Let $W_{\text{line}}$ be the natural width of the line tokens and $W_{\text{target}}$ the available column width:
- **`left`:** $X_{\text{start}} = X_{\text{col}} + \text{indent}_{\text{left}}$
- **`right`:** $X_{\text{start}} = X_{\text{col}} + \text{indent}_{\text{left}} + (W_{\text{target}} - W_{\text{line}})$
- **`center`:** $X_{\text{start}} = X_{\text{col}} + \text{indent}_{\text{left}} + \lfloor \frac{W_{\text{target}} - W_{\text{line}}}{2} \rfloor$
- **`both` (Justified):** Extra space $(W_{\text{target}} - W_{\text{line}}) / N_{\text{spaces}}$ is distributed equally across all inter-word space tokens.

## 5. Pagination Solver & Document Constraints

The `PaginationSolver` streams paragraph blocks into a multi-column page model while enforcing Word's four core pagination rules:

1. **`w:pageBreakBefore`:** Forces an immediate advance to a new page whenever content already exists on the current page ($Y > \text{margin}_{\text{top}}$).
2. **`w:keepLines`:** If the total height of all lines in a paragraph exceeds the remaining column height ($H_{\text{para}} > H_{\text{rem}}$), the entire paragraph is moved to the next column or page, preventing intra-paragraph page splits.
3. **`w:keepNext`:** If paragraph $P_k$ has `keep_next == true` and the subsequent paragraph $P_{k+1}$ cannot fit at least one line in the remaining space, $P_k$ is moved to the next page to accompany $P_{k+1}$, eliminating orphaned headings.
4. **`w:widowControl`:**
   - **Orphan Prevention:** Minimum of 2 lines must remain on the first page ($k \ge 2$). If only 1 line fits, the entire paragraph moves to the next page ($k \to 0$).
   - **Widow Prevention:** Minimum of 2 lines must be carried over to the second page ($L - k \ge 2$). If only 1 line would be carried over ($L - k = 1$), one additional line is pushed to the second page.
   - For a 3-line paragraph ($L = 3$), since it can split neither $1+2$ (orphan) nor $2+1$ (widow), all 3 lines move together to the next page.
5. **Multi-Column Flow:** Content flows through column $0$, column $1$, $\dots$, column $M-1$ on page $P$ before advancing to page $P+1$.
