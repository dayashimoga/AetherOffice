## 1. Clean-Room Architecture & Data Structures

### 1.1 ECMA-376 §17.7 Hierarchical Style Cascade Resolver

The style cascade in WordprocessingML resolves final computed typographical and paragraph layout properties across multiple inheritance layers. The OpenOfficeRS `StyleCascadeResolver` executes this resolution in strict adherence to ECMA-376 Part 1 §17.7:

$$\text{docDefaults} \longrightarrow \text{tableStyle} \longrightarrow \text{paragraphStyle} \longrightarrow \text{characterStyle} \longrightarrow \text{directFormatting}$$

```
                                  +----------------------+
                                  |    docDefaults       |
                                  | (pPrDefault/rPrDef)  |
                                  +----------+-----------+
                                             |
                                             v
                                  +----------------------+
                                  |     Table Style      |
                                  | (wholeTable / condPr)|
                                  +----------+-----------+
                                             |
                                             v
                                  +----------------------+
                                  |   Paragraph Style    |
                                  | (basedOn inheritance)|
                                  +----------+-----------+
                                             |
                                             v
                                  +----------------------+
                                  |   Character Style    |
                                  | (basedOn inheritance)|
                                  +----------+-----------+
                                             |
                                             v
                                  +----------------------+
                                  |  Direct Formatting   |
                                  |  (w:pPr / w:rPr)     |
                                  +----------------------+
```

#### Cycle Safety in `basedOn` Chains
Styles can reference an ancestor style via `<w:basedOn w:val="..."/>`. To guarantee terminating lookups under corrupt or adversarial documents, `StyleCascadeResolver` maintains a cycle-detection set (`HashSet<&str>`). If a cycle is detected ($A \to B \to A$), chain traversal terminates immediately and logs a clean fallback without crashing or panicking.

#### Toggle Property Inversion Rules (ECMA-376 Part 1 §17.7.3)
Run properties such as bold (`w:b`), italic (`w:i`), and strikethrough (`w:strike`) are classified as *toggle properties*.
- Under ECMA-376 §17.7.3, when a direct run format element `<w:b/>` is present without an explicit `val` attribute (or `val="1"`, `val="true"`), it does not merely assert `true`; it **inverts** the value inherited from the preceding cascade layers.
- If a style resolved bold as `true`, direct `<w:b/>` flips the final resolved value to `false`.
- If a style resolved bold as `false` or unset, direct `<w:b/>` flips the final resolved value to `true`.

#### Table Style Conditional Formatting (`w:tblStylePr`)
Table styles define conditional overrides applied based on cell coordinates:
- `firstRow`: Applied to header row ($r = 0$).
- `lastRow`: Applied to total row ($r = R - 1$).
- `band1Horz`: Applied to alternating row bands ($r \pmod 2 = 1$).
- `band1Vert`: Applied to alternating column bands ($c \pmod 2 = 1$).
- `nwCell`, `neCell`, `swCell`, `seCell`: Applied to top-left, top-right, bottom-left, and bottom-right corner cells.

## 2. Multi-Level List Numbering Engine (`word/numbering.xml`)

### 2.1 State-Machine Architecture
The `NumberingEngine` implements the list numbering model defined in ECMA-376 Part 1 §17.9:
1. **Abstract Numbering Definitions (`w:abstractNum`):** Defines the list topology, multi-level hierarchy (levels 0 through 8), prefix template string (`w:lvlText`), formatting format (`w:numFmt`), indentation (`w:pPr`), and restart behavior (`w:lvlRestart`).
2. **Numbering Instances (`w:num`):** Binds a concrete `numId` to an `abstractNumId`, with optional instance-level level overrides (`w:lvlOverride`) and start counters (`w:startOverride`).
3. **Counter State Tracking:** Maintains counter arrays indexed by `(num_id, ilvl)`.

### 2.2 Supported Number Formats
The formatting engine translates positive integer counters into standard string representations:
- **`decimal`:** `"1"`, `"2"`, `"3"`, $\dots$
- **`lowerLetter`:** Standard base-26 bijective alphabetical sequence: `"a"`, `"b"`, $\dots$, `"z"`, `"aa"`, `"ab"`, $\dots$
- **`upperLetter`:** `"A"`, `"B"`, $\dots$, `"Z"`, `"AA"`, `"AB"`, $\dots$
- **`lowerRoman`:** Classical additive/subtractive Roman numerals in lowercase: `"i"`, `"iv"`, `"ix"`, `"xiv"`, `"xl"`, `"xc"`, `"cd"`, `"cm"`, $\dots$
- **`upperRoman`:** Classical Roman numerals in uppercase: `"I"`, `"IV"`, `"IX"`, `"XIV"`, $\dots$
- **`bullet`:** Static glyph character, e.g. `•` (U+2022), `-`, `–`.
- **`ordinal`:** English ordinal representation: `"1st"`, `"2nd"`, `"3rd"`, `"4th"`, `"11th"`, `"21st"`, $\dots$
- **`cardinalText`:** English cardinal word representation: `"one"`, `"twelve"`, `"twenty-one"`, `"one hundred five"`, $\dots$

### 2.3 Level Restart Logic (`w:lvlRestart`)
When a list item increments a level counter at depth $k$, all descendant levels $j > k$ reset their current counters to their designated starting value (`start` or `startOverride`). This ensures sequential sub-numbering:
$$1.1 \to 1.2 \to 2.1 \text{ (level 1 resets to 1)}$$

### 2.4 Multi-Level Template String Interpolation
Prefix strings defined in `<w:lvlText w:val="%1.%2.%3"/>` dynamically substitute `%k` placeholders with the formatted string of level $k-1$ for all levels in the active hierarchy.

## 3. Section Geometry & Coordinate Transformations

### 3.1 Geometric Representation
The `SectionGeometry` model computes layout boundaries for page rendering and pagination:
- **Twip Arithmetic:** $1\text{ pt} = 20\text{ twips}$; $1\text{ inch} = 72\text{ pt} = 1440\text{ twips}$; $1\text{ mm} = 56.6929\text{ twips}$.
- **Page Dimensions:** Width $W_{\text{page}}$ and Height $H_{\text{page}}$ in twips (e.g. US Letter $= 12240 \times 15840\text{ twips}$, A4 $= 11906 \times 16838\text{ twips}$).
- **Content Box:**
  $$\text{ContentWidth} = W_{\text{page}} - \text{margin}_{\text{left}} - \text{margin}_{\text{right}} - \text{gutter}$$
  $$\text{ContentHeight} = H_{\text{page}} - \text{margin}_{\text{top}} - \text{margin}_{\text{bottom}}$$

### 3.2 Multi-Column Division
For multi-column sections with $N$ equal columns separated by inter-column spacing $S$:
$$W_{\text{col}} = \frac{\text{ContentWidth} - (N - 1) \cdot S}{N}$$
$$\text{X}_{\text{start}}^{(i)} = \text{margin}_{\text{left}} + \text{gutter} + i \cdot (W_{\text{col}} + S) \quad \text{for } i \in [0, N-1]$$
Supports both uniform column widths and custom heterogeneous column widths.

## 4. Package Integration & Round-Trip Fidelity

`WordPackage` integrates `StyleSheet` and `Numbering`:
1. **Model Synchronization:** Parses `word/styles.xml` into a typed `StyleSheet` and `word/numbering.xml` into a typed `Numbering` model.
2. **Lossless Coexistence:** Retains raw XML parts in `UnparsedPartStore` to guarantee 100% bit-exact baseline round-trip when unedited, and updates serialized XML on save when modified.
3. **Direct Helper Access:** Exposes `pkg.cascade_resolver()` and `pkg.section_geometry()` for the render tree and layout engine.
