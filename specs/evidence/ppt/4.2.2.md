## 1. Clean-Room Morph Transition (`p159:morph`) Mathematical Specification

The Morph transition animates smooth movement, transformation, deformation, and textual change between two adjacent slides $S_A$ (source) and $S_B$ (target).

### 1.1 Shape Correspondence & Matching Rules

Each slide contains a set of shapes $S_A = \{a_1, a_2, \dots, a_M\}$ and $S_B = \{b_1, b_2, \dots, b_N\}$. Shapes are mapped into three disjoint sets:
1. Matched shape pairs: $M_{\text{pair}} = \{(a_i, b_j)\}$
2. Exiting shapes (in $S_A$, not in $S_B$): $U_A = \{a_i\}$
3. Entering shapes (not in $S_A$, in $S_B$): $U_B = \{b_j\}$

#### 1. Explicit Exclamation-Mark (`!!`) Identifier Rule
PowerPoint provides an explicit user override mechanism:
- If a shape name in $S_A$ begins with `"!!"`, e.g. `"!!HeaderBox"` or `"!!Hero"`, and a shape in $S_B$ has the exact same name `"!!HeaderBox"`, these shapes are guaranteed to correspond with priority 1.
- Explicit matches are removed from the candidate pool prior to heuristic matching.

#### 2. Automatic Heuristic Correspondence Scoring
For all remaining unmatched pairs $(a_i, b_j)$, compute a normalized similarity score $\mathcal{S}(a_i, b_j) \in [0.0, 1.0]$:

$$\mathcal{S}(a_i, b_j) = w_{\text{geom}} \cdot s_{\text{geom}} + w_{\text{pos}} \cdot s_{\text{pos}} + w_{\text{size}} \cdot s_{\text{size}} + w_{\text{text}} \cdot s_{\text{text}}$$

where the weights are:
- $w_{\text{geom}} = 0.35$ (Geometry / Type similarity)
- $w_{\text{pos}} = 0.25$ (Normalized spatial proximity)
- $w_{\text{size}} = 0.20$ (Bounding box area ratio)
- $w_{\text{text}} = 0.20$ (Textual content similarity)

**Sub-metric definitions:**
- **Geometry similarity $s_{\text{geom}}$:**
  $$s_{\text{geom}} = \begin{cases} 1.0 & \text{if preset geometry types are identical (e.g. } \text{rect} = \text{rect}) \\ 0.5 & \text{if both are rectangular variants (e.g. } \text{rect} \leftrightarrow \text{roundRect}) \\ 0.0 & \text{otherwise} \end{cases}$$

- **Position similarity $s_{\text{pos}}$:**
  Let $(cx_a, cy_a)$ and $(cx_b, cy_b)$ be the shape center coordinates in slide canvas dimensions $(W_{\text{slide}}, H_{\text{slide}})$:
  $$d_{\text{norm}} = \sqrt{\left(\frac{cx_a - cx_b}{W_{\text{slide}}}\right)^2 + \left(\frac{cy_a - cy_b}{H_{\text{slide}}}\right)^2}$$
  $$s_{\text{pos}} = \max\left(0.0, 1.0 - \frac{d_{\text{norm}}}{\sqrt{2}}\right)$$

- **Size similarity $s_{\text{size}}$:**
  Let $A_a = w_a \cdot h_a$ and $A_b = w_b \cdot h_b$ be bounding box areas:
  $$s_{\text{size}} = \frac{\min(A_a, A_b)}{\max(A_a, A_b)}$$

- **Text similarity $s_{\text{text}}$:**
  If both shapes contain text, $s_{\text{text}}$ is the normalized Jaccard character bigram similarity:
  $$s_{\text{text}} = \frac{|B(T_a) \cap B(T_b)|}{|B(T_a) \cup B(T_b)|}$$
  If neither shape contains text, $s_{\text{text}} = 1.0$. If exactly one contains text, $s_{\text{text}} = 0.0$.

**Matching Decision:**
Pairs with $\mathcal{S}(a_i, b_j) \ge 0.45$ are matched greedily by descending similarity score.

### 1.2 Equal-Subdivision Cubic Bezier Path Morphing

When morphing between two shapes with different geometries or vertex counts (e.g., triangle with 3 vertices morphing into a circle or 5-point star):

#### 1. Conversion to Cubic Bezier Segments
All DrawingML path commands are converted to standard cubic Bezier segments $B(u) = (1-u)^3 P_0 + 3(1-u)^2 u C_1 + 3(1-u) u^2 C_2 + u^3 P_3$:
- `LineTo(P_1)` from $P_0$:
  $$C_1 = P_0 + \frac{1}{3}(P_1 - P_0), \quad C_2 = P_0 + \frac{2}{3}(P_1 - P_0), \quad P_3 = P_1$$
- `QuadBezTo(C, P_1)` from $P_0$:
  $$C_1 = P_0 + \frac{2}{3}(C - P_0), \quad C_2 = P_1 + \frac{2}{3}(C - P_1), \quad P_3 = P_1$$
- `CubicBezTo(C_1, C_2, P_1)`: directly mapped.

#### 2. Arc-Length Parameterization & Equal Subdivision
Let $P_A$ have $m$ segments and $P_B$ have $n$ segments. To avoid vertex popping, both paths are re-parameterized into an equal number of cubic segments $N = \max(m, n, 8)$.
- For path $P$, cumulative arc length $L(u)$ is approximated by sampling Gauss-Legendre quadratures.
- For each subdivision $k \in \{0, 1, \dots, N-1\}$, the normalized parameter $s_k = \frac{k}{N}$ locates the arc-length position $s_k \cdot L_{\text{total}}$.
- The evaluated position and tangent vectors define the normalized cubic Bezier control points:
  $$S_{A,k} = (P_{0,A}^k, C_{1,A}^k, C_{2,A}^k, P_{3,A}^k), \quad S_{B,k} = (P_{0,B}^k, C_{1,B}^k, C_{2,B}^k, P_{3,B}^k)$$

#### 3. Continuous Time Interpolation ($t \in [0.0, 1.0]$)
For each segment $k \in \{0, \dots, N-1\}$:
$$P_0(t) = (1 - t) P_{0,A}^k + t P_{0,B}^k$$
$$C_1(t) = (1 - t) C_{1,A}^k + t C_{1,B}^k$$
$$C_2(t) = (1 - t) C_{2,A}^k + t C_{2,B}^k$$
$$P_3(t) = (1 - t) P_{3,A}^k + t P_{3,B}^k$$

At $t = 0$, the path evaluates identically to Shape A. At $t = 1$, it evaluates identically to Shape B. Across $t \in (0, 1)$, deformation is $C^1$ smooth.

### 1.3 Text Morphing (`byObject`, `byWord`, `byChar`)

1. **`byObject` (Default):**
   The entire text body moves, scales, and rotates as a single rigid bounding box bound to the shape transform.
2. **`byWord`:**
   Text strings are tokenized into whitespace-delimited words. Words with identical text are matched sequentially. Matched words linearly interpolate their $(x, y)$ positions, font sizes, and text colors. Unmatched words on Slide A fade out ($1.0 \to 0.0$); unmatched words on Slide B fade in ($0.0 \to 1.0$).
3. **`byChar`:**
   Characters are aligned via Myers diff / Longest Common Subsequence (LCS). Matched characters interpolate individual $(x, y)$ canvas coordinates, font sizes, and color channels. Displaced characters fly smoothly to their new positions.

## 2. SmartArt Constraint Layout Engine (`ppt/diagrams/layout*.xml`, `dgm:alg`)

ECMA-376 Part 1 §21.4 specifies the SmartArt diagram architecture:
- `ppt/diagrams/data1.xml` (`dgm:dataModel`): Abstract point graph ($V, E$)
- `ppt/diagrams/layout1.xml` (`dgm:layoutDef`): Algorithmic constraints (`dgm:alg`)
- `ppt/slides/slide1.xml` (`p:spTree`): Static pre-rendered DrawingML shape tree cache for compatibility.

### 2.1 Supported Layout Algorithms (`dgm:alg`)

#### 1. Linear Layout (`lin`)
Arranges $N$ data points along a straight line inside bounding box $(x, y, w, h)$.
- **Horizontal (`horz`):**
  $$w_{\text{item}} = \frac{w - (N - 1) \cdot \text{gap}}{N}, \quad h_{\text{item}} = h$$
  $$x_i = x + i \cdot (w_{\text{item}} + \text{gap}), \quad y_i = y$$
- **Vertical (`vert`):**
  $$w_{\text{item}} = w, \quad h_{\text{item}} = \frac{h - (N - 1) \cdot \text{gap}}{N}$$
  $$x_i = x, \quad y_i = y + i \cdot (h_{\text{item}} + \text{gap})$$

#### 2. Pyramid Layout (`pyra`)
Stacks $N$ horizontal trapezoidal tiers vertically inside bounding box $(x, y, w, h)$.
- Tier height: $h_i = \frac{h}{N}$.
- Top tier $i = 0$ has apex width $w_0 = w \cdot \frac{1}{N}$.
- Tier $i$ has top width $w_{\text{top},i} = w \cdot \frac{i}{N}$ and bottom width $w_{\text{bot},i} = w \cdot \frac{i+1}{N}$.
- Center of each tier is horizontally aligned at $x + \frac{w}{2}$.

#### 3. Cycle Layout (`cycle`)
Arranges $N$ nodes radially along an ellipse centered at $(cx, cy) = (x + \frac{w}{2}, y + \frac{h}{2})$:
- Radii: $R_x = \frac{w - w_{\text{node}}}{2}, \quad R_y = \frac{h - h_{\text{node}}}{2}$.
- Node angles:
  $$\theta_i = -\frac{\pi}{2} + i \cdot \frac{2\pi}{N}$$
  $$x_i = cx + R_x \cos(\theta_i) - \frac{w_{\text{node}}}{2}, \quad y_i = cy + R_y \sin(\theta_i) - \frac{h_{\text{node}}}{2}$$

#### 4. Hierarchy Layout (`hierChild`)
Arranges tree nodes hierarchically from root to leaves:
- Depth levels $0, 1, \dots, D-1$. Level height $h_{\text{level}} = \frac{h}{D}$.
- Within each level, siblings are horizontally centered beneath their parent node.
- Orthogonal routing lines link parent bottom centers to child top centers.

#### 5. Snake Layout (`snake`)
Arranges nodes in a zig-zag grid of $C$ columns:
- Row $r = \lfloor i / C \rfloor$, column index $c$.
- Even rows ($r \equiv 0 \pmod 2$): $c = i \pmod C$ (left to right).
- Odd rows ($r \equiv 1 \pmod 2$): $c = C - 1 - (i \pmod C)$ (right to left).

## 3. Shape Tree (`p:spTree`) Cache Synchronization

When SmartArt diagram data or layout changes, the engine automatically synchronizes and updates the static `p:spTree` shapes:
- Generates DrawingML shape nodes `<p:sp>` with calculated transforms (`a:off`, `a:ext`), preset geometries (`a:prstGeom`), fill colors, and formatted text paragraphs.
- Guarantees complete visual presentation in downstream viewers that do not execute dynamic `dgm:layoutDef` layout scripts.
