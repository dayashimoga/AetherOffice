## 1. Clean-Room Reverse Engineering Analysis: 3-Tier Inheritance Cascade

PresentationML employs a 3-tier hierarchical inheritance model to separate presentation-wide branding, slide structural layouts, and specific slide content:

```
                            +-------------------------+
                            |     Theme (theme.xml)   |
                            |  - a:clrScheme (12 clrs)|
                            |  - a:fontScheme         |
                            +------------+------------+
                                         |
                                         v
                            +-------------------------+
                            | SlideMaster (*.xml)     |
                            |  - p:clrMap             |
                            |  - p:txStyles           |
                            |  - Master Placeholders  |
                            +------------+------------+
                                         |
                                         v
                            +-------------------------+
                            | SlideLayout (*.xml)     |
                            |  - p:clrMapOvr          |
                            |  - Layout Placeholders  |
                            +------------+------------+
                                         |
                                         v
                            +-------------------------+
                            |      Slide (*.xml)      |
                            |  - Content Overrides    |
                            |  - Direct Formatting    |
                            +-------------------------+
```

### 1.1 Placeholder Shape Matching Rules
When resolving a placeholder shape $S_{\text{slide}}$ on a slide:
1. **Index-Based Matching (`idx`):**
   If $S_{\text{slide}}$ defines an explicit placeholder index $I \in \mathbb{N}$ via `<p:ph idx="I" />`:
   - Match the first shape $S_{\text{layout}}$ on the layout with $\text{ph.idx} == I$.
   - If not found on layout, match $S_{\text{master}}$ on the master with $\text{ph.idx} == I$.
2. **Type-Based Matching (`type`):**
   If $\text{idx}$ is omitted or unmatched, match by placeholder type:
   $$\text{ph.type}(S_{\text{slide}}) = \text{ph.type}(S_{\text{target}})$$
   Standard placeholder types include `title`, `ctrTitle`, `subTitle`, `body`, `dt`, `ftr`, `sldNum`, `pic`, `tbl`, `chart`, `dgm`.
3. **ECMA-376 Fallback Compatibility Rules (§19.3.1.36):**
   - A centered title placeholder (`ctrTitle`) falls back to match a `title` placeholder on the master if no `ctrTitle` placeholder exists on the master.
   - A subtitle placeholder (`subTitle`) falls back to match a `body` placeholder on the layout/master if no `subTitle` placeholder exists on the layout/master.

### 1.2 Shape Visual Property Inheritance
Properties are resolved hierarchically from most specific to least specific:
$$P(S) = \begin{cases} 
P(S_{\text{slide}}) & \text{if explicitly defined} \\
P(S_{\text{layout}}) & \text{else if defined on matched layout placeholder} \\
P(S_{\text{master}}) & \text{else if defined on matched master placeholder} \\
P_{\text{default}} & \text{otherwise}
\end{cases}$$

- **Transform2D (`a:xfrm`):** Offset $(X, Y)$ and Extents $(C_X, C_Y)$ in EMUs ($1\text{ pt} = 12,700\text{ EMUs}$; $1\text{ inch} = 914,400\text{ EMUs}$).
- **Geometry (`a:prstGeom` / `a:custGeom`):** Preset shapes (`rect`, `roundRect`, `ellipse`, etc.) or custom paths.
- **Fill & Line:** Solid fills, scheme fills, gradient fills, and stroke outlines with dash patterns.

## 2. Text Formatting Cascade & Multi-Level List Hierarchy

Inside placeholder text bodies, paragraph and run properties cascade through four cascading tiers:

1. **Tier 1 (Direct Formatting):** Properties explicitly present on the slide run (`a:rPr`) or paragraph (`a:pPr`).
2. **Tier 2 (Shape List Style):** Shape-level `<a:lstStyle>` defined within `<p:txBody>`.
3. **Tier 3 (Master Text Styles):** Defined under `<p:txStyles>` in the slide master:
   - For `title`, `ctrTitle`, `subTitle`: resolved from `txStyles.title_style`.
   - For `body`, `obj`: resolved from `txStyles.body_style`.
   - For arbitrary non-placeholder text boxes: resolved from `txStyles.other_style`.
   Indexed by paragraph level $L \in \{0, \dots, 8\}$ corresponding to `<a:lvl1pPr>` through `<a:lvl9pPr>`.
4. **Tier 4 (Presentation Default):** Fallback to `<p:defaultTextStyle>` defined in `presentation.xml`.

## 3. Theme Color Scheme Resolution & Transformations

### 3.1 Color Scheme & Role Mapping
Theme defines 12 standard color tokens under `<a:clrScheme>`:
- Base: `dk1`, `lt1`, `dk2`, `lt2`
- Accents: `accent1`, `accent2`, `accent3`, `accent4`, `accent5`, `accent6`
- Hyperlinks: `hlink`, `folHlink`

The slide master maps presentation semantic roles (`bg1`, `tx1`, `bg2`, `tx2`, `accent1`..`accent6`, `hlink`, `folHlink`) to theme color tokens via `<p:clrMap>`. Slides and layouts may override this mapping via `<p:clrMapOvr><a:overrideClrMapping ... /></p:clrMapOvr>`.

### 3.2 Color Transformation Mathematical Equations
When scheme colors are decorated with child transformation filters:

1. **Tint (`<a:tint val="T" />` where $t = T / 100,000$):**
   Linear interpolation towards pure white ($255, 255, 255$):
   $$C' = \text{round}(C + (255 - C) \cdot t)$$
2. **Shade (`<a:shade val="S" />` where $s = S / 100,000$):**
   Linear interpolation towards pure black ($0, 0, 0$):
   $$C' = \text{round}(C \cdot s)$$
3. **Luminance Modulation & Offset (`<a:lumMod val="M" />`, `<a:lumOff val="O" />`):**
   Convert RGB to HSL $(H, S, L)$ where $L \in [0.0, 1.0]$:
   $$L' = \text{clamp}\left(L \cdot \frac{M}{100,000} + \frac{O}{100,000}, 0.0, 1.0\right)$$
   Convert $(H, S, L')$ back to RGB.
4. **Alpha Opacity (`<a:alpha val="A" />`):**
   $$\text{alpha} = \lfloor \frac{A \cdot 255}{100,000} \rfloor$$

## 4. Theme Font Scheme Resolution

Theme font tokens are resolved cleanly to target typography:
- `+mj-lt`: Major Latin typeface from `<a:majorFont><a:latin typeface="..." /></a:majorFont>` (used for slide titles and headings).
- `+mn-lt`: Minor Latin typeface from `<a:minorFont><a:latin typeface="..." /></a:minorFont>` (used for body text, bullet lists, and tables).
- `+mj-ea` / `+mn-ea`: East Asian major and minor typefaces.
- `+mj-cs` / `+mn-cs`: Complex script major and minor typefaces.
