## 1. Clean-Room Reverse Engineering Analysis: Excel IEEE-754 Snap-to-Zero Heuristic

### 1.1 The Anomaly
In IEEE-754 double precision (64-bit binary floating-point, 53 bits significand), decimal fractions cannot be represented with exact binary precision:
- $1.333_{10} = \text{0x3ff553f7ced91687}$ ($1.33299999999999996269...$)
- $1.225_{10} = \text{0x3ff399999999999a}$ ($1.22500000000000008881...$)
- $0.108_{10} = \text{0x3fbbad02b4fcb5e7}$ ($0.10800000000000001265...$)

Direct IEEE-754 subtraction yields:
$$(1.333 - 1.225) - 0.108 = -1.2490009027033011 \times 10^{-16}$$

In Microsoft Excel (`EXCEL.EXE`):
1. Entering `=1.333 - 1.225 - 0.108` displays and stores **`0.0`**.
2. Entering `=(1.333 - 1.225 - 0.108)` displays and stores **`-1.2490009027033011E-16`**.

### 1.2 Clean-Room Mathematical Rule
Through empirical COM differential harness analysis (`tools/com-ground-truth/generate_truth.py`), the snap heuristic rule is defined as follows:

Let $E$ be an Excel formula expression.
1. The snap heuristic applies **only** if the root operation of $E$ is binary addition or subtraction ($+$ or $-$):
   $$E = A \pm B$$
2. If $E$ is enclosed in parentheses:
   $$E = ( A \pm B )$$
   the root AST node is `Parenthesized`, so the snap heuristic is **suppressed**, preserving raw IEEE-754 precision.
3. For root additive expressions:
   Let $S = \max(|A|, |B|)$ be the operand scale.
   If $S > 0.0$, the relative residual is:
   $$\text{rel} = \frac{|A \pm B|}{S}$$
   If $\text{rel} \le \tau$, where $\tau = 2.842170943040401 \times 10^{-14}$ ($\approx 2^{-45}$, representing truncation beyond 15-16 decimal digits), the result snaps to $0.0$:
   $$\text{snap}(A \pm B) = \begin{cases} 0.0 & \text{if } |A \pm B| \le S \cdot \tau \\ A \pm B & \text{otherwise} \end{cases}$$
4. For non-additive operations (multiplication, division, functions, literals), raw IEEE-754 precision is preserved.

## 2. Calculation DAG & Calc Chain Engine Architecture

Subphase 2.2.2 implements `crates/excel-engine/src/calc_dag.rs`:

1. **Cell Addressing (`CellKey`):** Global tuple `(sheet_idx, row, col)` indexing cells across worksheets in a workbook.
2. **Directed Acyclic Graph (`CalculationDag`):**
   - Bidirectional edges: `dependents: HashMap<CellKey, HashSet<CellKey>>` and `predecessors: HashMap<CellKey, HashSet<CellKey>>`.
   - Automatic AST reference extraction: parses cell addresses, 2D ranges, and dynamic array spills (`#`) to register dependency edges.
3. **Dirty-Flag Propagation:**
   - When a cell value changes, `mark_dirty(cell)` performs breadth-first traversal, marking all downstream transitive dependents dirty.
   - Recalculation evaluates only dirty cells, achieving $O(K)$ evaluation latency where $K$ is the number of affected cells.
4. **Tarjan's Strongly Connected Components (SCC) Cycle Detection:**
   - Detects all circular reference loops (self-referential $A_1 \to A_1$, mutual $A_1 \leftrightarrow B_1$, and multi-node $A_1 \to B_1 \to C_1 \to A_1$).
5. **Iterative Calculation Convergence (`calcPr`):**
   - If circular dependencies exist and `iter_config.enabled == true`, Gauss-Seidel relaxation iterates cyclic cells up to `max_iterations` (default 100) or until $\max(\Delta) \le \text{max\_change}$ (default 0.001).
   - If iteration is disabled, circular references return typed `EngineError::FormulaError`.
6. **ECMA-376 `xl/calcChain.xml` Integration:**
   - Streaming quick-xml parser and serializer for the calculation sequence `<calcChain><c r="A2" i="1"/>...</calcChain>`.
